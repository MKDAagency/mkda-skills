# MKDA basics for video scripts

The user's layer wins over this page.

## Writing

- One line, one idea. Short lines made to be spoken.
- About 2.5 words a second: 75-100 words are 30-40 seconds.
- Numbers in digits. No em dashes. Correct accents and spelling.
- Plain language; explain each technical term in everyday words.
- Hook: in the first 3 seconds name the viewer's problem or situation, not the product.
- Every question in the script gets a real answer, never "contact us and we'll explain".
- Positive and generous: no fear, no provocation, no attacks on competitors.
- Nothing that can expire before it airs: prices, promotions, stock.

## Facts

- Every fact has a source and the date it was checked, in `source`. Start from the business's own pages, read today.
- What cannot be verified is not promised: it goes in `to_confirm`.
- A claim on a landing page is not a verified fact. Percentages, "100%", "zero" only if they hold up.
- Tax, legal, health: point to the professional instead of giving figures.

## The batch

- 5 scripts by default, one per awareness level: Unaware, Problem Aware, Solution Aware, Product Aware, Most Aware.
- 1 video in 5 is about the brand. Vary the audience.
- A topic limit from the client takes one script; the others stay free.
- Never repeat a topic, even with a new angle: same means, same lever or same question counts as a repeat.
- Each script starts from a fact read today that no past script used.
- Delicate hook or direct comparison: add a more careful alternative right after (`2B`).

## Call to action

One main action per script. Say where to go and what to do, concretely.

## Shape of the message

It follows the business:

- Commercial: problem, solution, proof, action.
- Educational: what it is, benefits, how it works, change, invitation.
- Evocative: slow lines, atmosphere, visual notes, close on the brand.

## Document

One script per page, a tick box for each line, never bullets or chained lists. Working notes (sources, confirmations, shoot notes) stay in the json.
